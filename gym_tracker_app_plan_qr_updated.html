App Plan

Simple Gym + Food Tracker

Build a fast mobile-first tracker centered on two daily jobs: log workouts quickly and track food simply. Since you train at LA Fitness, the workout logger should prioritize machine QR codes, instruction videos, saved routines, and one-tap reuse of your previous weights.

01 — Product Focus

Keep the first version intentionally small

Workout

Routine-based logging

Select a saved routine, then move exercise-by-exercise with previous performance already filled in.

Equipment

QR-first machine selection

Scan the code already on a machine, resolve it to the correct equipment model, show its instruction video, and jump directly into logging. Favorites and search remain as fallbacks.

Food

Simple meal tracking

Calories and protein first. Add carbs and fat if useful, but avoid building a giant nutrition database in v1.

Why this matters

You do not need a perfect global database of every LA Fitness location. Shared data can identify the generic equipment model and instructional media, while each user keeps their exact machine setup locally.

Core LA Fitness workflow

Scan → identify → learn → log

1

Scan QR

Use the phone camera to scan the code already attached to the machine.

2

Resolve Equipment

Match the destination URL to a known manufacturer/model or create a local mapping if unknown.

3

Show Video

Open or embed the machine's official instruction video and show setup notes.

4

Log Set

Jump straight to last weight/reps, seat position, rest timer, and the next set.

First-time scan

  • Read QR destination URL.
  • Check local mapping first.
  • If recognized in the community catalog, import equipment metadata.
  • If unknown, save the raw URL locally and let the user name/map the machine once.
  • Future scans of the same code open the logger immediately.

Machine screen

  • Machine name + manufacturer/model when known.
  • Official instruction video link.
  • Target muscles and associated exercises.
  • Last workout performance.
  • Seat/handle/setup notes for this exact machine.
  • Favorite + add-to-routine actions.

07 — Architecture

Private activity stays local. Shared knowledge goes to Convex.

The app should work fully without an account or network connection. A central server exists only where shared community data or identity is actually useful.

Local source of truth

Personal data

  • Workout history and individual sets
  • Personal routines and exercise order
  • Favorite machines at your gym
  • Personal QR-to-machine mappings and setup notes
  • Food log and personal meals
  • Body weight, goals, and preferences
  • Private notes and machine setup details
Central community

Convex data

  • Community workout templates
  • Shared exercise and equipment-model definitions
  • Known machine QR URL → equipment/video mappings
  • Public foods and recipes
  • Tags, ratings, and publishing
  • Reports and moderation
  • Optional public profiles
Importing a community routine or recipe should create a local copy. If the original author edits or deletes the public version later, the user's personal copy and history should not break.

Optional P2P sync

Phone ↔ laptop ↔ tablet should be able to exchange local records directly. Pair devices with a QR code or short pairing code. For the first version, use stable UUIDs, timestamps, device IDs, and soft deletes; full CRDT machinery can wait until real conflict cases justify it.

09 — Build Stack

Easy way to build it

Recommended

Local-first + optional Convex

  • React / Next.js for a mobile-first PWA.
  • IndexedDB for the local source of truth on web; SQLite if you later ship native.
  • Optional P2P device sync for workouts, food logs, routines, goals, and personal machine data.
  • Convex only for shared/community content such as public workouts, foods, recipes, ratings, and publishing.
  • Use Convex auth only when a feature genuinely needs identity.
Simplest prototype

HTML + IndexedDB

  • No account system and no server dependency.
  • Store workouts, food logs, favorites, routines, and settings locally.
  • Use IndexedDB instead of localStorage once the prototype stores meaningful data.
  • Later keep the same local-first model when moving to React and adding P2P sync.
10 — Build Roadmap

Build in this order

Phase 1

Local workout engine

Build the exercise catalog, QR scanner, local QR-to-machine mapping, personal machine favorites, routines, active workout logger, set history, instruction-video access, and previous-performance suggestions. Everything persists locally.

Phase 2

Local food engine

Add calories, protein, saved foods, saved meals, recipes, and quick manual entry. Personal nutrition history remains local by default.

Phase 3

P2P device sync

Pair devices with a QR code or device code and exchange local records directly. Start with UUIDs, timestamps, soft deletes, and simple conflict resolution before considering CRDTs.

Phase 4

Convex community layer

Add public routines, exercises, equipment-model metadata, known QR/video mappings, foods, recipes, tags, ratings, reports, and publishing. Community items can be imported into the user's local library.

Phase 5

Optional identity + polish

Add Convex auth only for publishing, profiles, ratings, moderation, or other identity-based community actions. Then add charts, body-weight trends, photos, and install polish.

11 — MVP Definition

When the first version is “done”

  • You can open the app at LA Fitness and start a routine in two taps.
  • Your favorite machines appear before the full exercise library.
  • Scanning a known machine QR code opens that machine's logger and instruction video with minimal taps.
  • An unknown QR code can be mapped once and remembered locally for future scans.
  • Each exercise shows the weight and reps from your previous session.
  • You can log a set with almost no typing.
  • Your completed workout is saved automatically.
  • You can enter a meal in under 30 seconds.
  • The home screen shows today's workout status, calories, and protein.
  • The core app works offline and without creating an account.
  • Personal workout and nutrition history never requires a central server.
  • Community content can be imported without becoming dependent on the original public item.
Best first move: prototype the entire workout loop locally before adding any backend. Build Home → Routine → scan machine QR → identify machine → instruction video / setup notes → Set logger → local history. Then add food, then P2P, and only after that add the Convex community layer.
