Plan · Gym Zero

One shared Claude key, metered and capped per person

Today every user has to paste in their own AI endpoint and key. This plan moves one official Anthropic API key onto the server so everyone you invite gets AI out of the box. You can see what each person spends and cap or cut off anyone.

The plan in five lines
  1. The key lives only on the server, as a Convex environment variable. It is never sent to a phone.
  2. Phones call a Convex action (ai.run), not the AI directly. The action checks who you are and whether you're under your limit, then calls Anthropic.
  3. The server owns the prompts. The phone sends "food photo + note", not a free-form prompt, so nobody can use your key as a general-purpose chatbot.
  4. Every call is logged with its tokens and cost, which feeds an admin-only AI usage card in Settings.
  5. Limits are layered: a per-person monthly $ cap, a burst rate limit, a block switch, a global kill switch, and a hard spend cap in the Anthropic Console as the last backstop.
  6. Bring-your-own-key stays. Each person picks Household AI (the server key, metered) or Your own key (Anthropic, OpenAI, or a custom endpoint like your CLIProxyAPI). Own-key calls go straight from the phone and never count against the household budget.

Today vs. after

The current design calls the AI straight from the phone because your CLIProxyAPI is reachable only on your tailnet, so a server hop would break it. Anthropic's API is public, so for the shared key the server hop is now the right design. It's the only place a secret can live safely. The direct path stays as Your own key, because the server can't reach your tailnet.

Adding the key (one-time, ~5 minutes)

Your Convex is self-hosted, so the key goes in the same place as BETTER_AUTH_SECRET and INVITE_CODE already do: Convex's environment, not docker-compose.yml and never a VITE_* variable. Anything prefixed VITE_ gets baked into the JavaScript every phone downloads.

1 · In the Anthropic Console

Create a workspace called gym-zero so this app's spend is separate from anything else you use the key for.

Set a workspace monthly spend limit (e.g. $25). It's a hard ceiling enforced by Anthropic even if our code has a bug.

Create an API key inside that workspace.

2 · Into Convex

# same shell setup as DEPLOY.md step 7
export CONVEX_SELF_HOSTED_URL=https://convex.…
export CONVEX_SELF_HOSTED_ADMIN_KEY='…'
npx convex env set ANTHROPIC_API_KEY sk-ant-…
npx convex env set AI_ADMIN_EMAILS you@example.com
npx convex env set AI_USER_MONTHLY_USD 1

Defaults come from env vars; per-person overrides are set in the app. The self-hosted backend needs outbound HTTPS to api.anthropic.com.

What happens on one food photo

Why reserve before calling? If someone fires five photo logs at once, each one checks the limit before any of them has finished and been billed. Reserving an estimate first closes that gap. The reservation becomes the real cost when the call finishes, or zero if it failed.

The five layers of limits

From the most specific to the last resort. A request has to pass all of them.

Per-person rateStops a runaway loop or a stuck button: e.g. 15 calls / 10 min and 40 photos / day, via the @convex-dev/rate-limiter component.automatic
Per-person $ / monthDefault from AI_USER_MONTHLY_USD; you can raise or lower it per person. Resets on the 1st.you set
Block personInstantly turns AI off for one account; the rest of the app keeps working.you toggle
Global pause / capOne switch turns off shared AI for everyone; the monthly total cap is AI_GLOBAL_MONTHLY_USD.you toggle

When someone hits a limit, AI buttons gray out with a reason ("Monthly AI limit reached, resets Nov 1"), the same pattern the app already uses when the proxy is unreachable. Manual entry always works.

Build order

1

Server call path core

  • Add @anthropic-ai/sdk and a Convex action ai.run({ feature, input }) that requires a signed-in user.
  • Move the system prompts and response cleanup out of src/lib/ai.ts into a shared module that both the client and Convex import. The phone sends only the feature's inputs, with size caps (note ≤ 1,000 chars, one photo ≤ ~1 MB).
  • Convert the OpenAI-style image_url data URL into Claude's base64 image block. Drop temperature, which current Claude models reject, and the OpenAI response_format.
  • Map Claude errors to the app's existing friendly messages, including stop_reason: "refusal".

Metering

Risks worth knowing

📷 Photo size

A 1280px JPEG is ~200–400 KB as base64, comfortably inside Convex's argument limit. The server still rejects anything oversized, so one bad upload can't make an expensive call.

⏱ One extra hop

Phone → Convex → Anthropic adds roughly 50–150 ms. That's small next to the AI's own response time.

🔒 Privacy

Food and equipment photos go to Anthropic under their API data terms. API traffic isn't used for training by default. Worth a line in the app for invitees.

🔑 Rotating the key

Run npx convex env set again. It takes effect immediately with no redeploy and no change on anyone's phone.

Questions for you

Each one changes what gets built. Recommended options are highlighted.

1 · What default monthly limit per person?
Why it matters: this is what everyone gets unless you change it. Typical use is about $0.15 a month and a heavy user about $0.45, so the cap mostly guards against bugs and abuse rather than normal use.
$0.50Tight. A heavy food-photo user could hit it late in the month.
$1RecommendedAbout 6× typical use. Nobody normal hits it, and a runaway costs at most $1.
$2+Roomy, if you plan to move reviews to Sonnet (Q5).
2 · Who is an admin?
Why it matters: the app has no roles today, and every invited account is equal. Someone has to be able to see everyone's usage and change limits.
Emails in an env var (AI_ADMIN_EMAILS)RecommendedNo new UI or schema. Changing admins is one command. Fine for a household.
An "admin" role in the databasePromote people from inside the app. More work, and only useful if admins change often.
3 · When someone's own key fails, fall back to Household AI?
Why it matters: your own-key setup points at a tailnet-only proxy, so whenever you're off Tailscale your AI goes gray. A fallback keeps it working, but those calls then spend household budget, a little.
Per-person switch, on by defaultRecommendedAI just works off the tailnet. A small "using Household AI" note shows when it happens, and anyone can turn it off (shown in the own-key sheet).
Never fall backOwn key means own key. You'd see the gray-out with "Can't reach your endpoint."
4 · What happens when someone hits their limit?
Why it matters: it decides whether a cap is a hard stop or a soft nudge.
Hard stop until the 1st, with the reason shownRecommendedPredictable, and matches the existing gray-out behavior. You can raise their limit from the admin card anytime.
Warn at 80%, stop at 100%Adds a small banner the user sees before they're cut off. Slightly more UI.
Let it through and just alert youNo interruptions, but then the cap isn't really a limit.
5 · Haiku or Sonnet for workout reviews and programs?
Why it matters: these are the only features where depth of reasoning shows. Sonnet is ~20× the price per token but only runs a few times a week, so it adds about $0.70 per person per month.
Start on Haiku, switch per feature if reviews feel thinRecommendedIt's one line in the model table, so you can decide after reading a few real reviews.
Sonnet from day oneBetter reviews immediately, about $10 per person per year instead of about $2.
6 · Should people see their own usage?
Why it matters: showing "$0.21 of $1" is transparent but puts money in front of family members, which some find awkward. Hiding it means the limit-reached message is their first sign of a cap.
Show a meter only after 50% usedRecommendedInvisible for normal use. It appears before anyone is surprised.
Always show itAs in the Household AI card mockup.
Never show itAdmin-only numbers.
